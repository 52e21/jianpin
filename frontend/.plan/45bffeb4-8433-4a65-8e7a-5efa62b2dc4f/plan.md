# **需求文档（修改版）：AI 招聘助手系统**

## **1. 应用概述**

**应用名称**：AI 招聘助手

**应用描述**：AI 招聘助手是一款面向 HR 和招聘团队的智能招聘辅助工具，通过 AI 技术自动完成岗位 JD 解析、候选人简历匹配、面试题生成与推荐结论汇总。系统采用简洁现代的科技风格设计，以蓝色为主色调，帮助招聘人员高效筛选人才、提升招聘效率。

## **2. 用户与使用场景**

**目标用户**：

* HR 招聘专员：需要快速筛选简历，匹配岗位需求
* 技术面试官：需要为候选人准备针对性的面试题目
* 招聘经理：需要获取候选人的综合推荐结论

**核心使用场景**：

1. **JD 录入**：HR 在输入框中粘贴岗位描述文本
2. **简历提交**：粘贴简历文本，或上传 PDF/Word 简历文件
3. **智能匹配**：系统自动计算候选人与岗位的匹配度，展示环形进度条
4. **面试题生成**：根据匹配结果自动生成针对性面试题目
5. **推荐结论**：系统给出推荐/待定/不推荐的综合评估
6. **历史管理**：查看过往匹配记录，支持搜索、分页、删除

## **3. 页面结构与功能说明**

### **页面结构**

text

AI 招聘助手/\
├── 任务执行页 (/) - 主页面\
└── 历史记录页 (/history) - 匹配历史列表

### **任务执行页 - 主功能**

**布局结构**：

* 顶部导航栏：品牌 Logo + 页面切换 + 主题切换
* 主内容区：卡片式布局，分阶段展示
* 页脚：版权信息 + 联系方式

**功能模块**：

1. **JD 输入区**
   * 文本输入框：支持多行输入岗位描述
   * 输入提示：提示用户粘贴完整 JD 内容
   * 示例 JD：可一键填入示例数据快速体验
2. **简历输入区**
   * 文本输入框：支持多行粘贴简历内容
   * 文件上传：支持 PDF/Word 格式简历文件，自动提取文字填入输入框
3. **JD 解析结果卡片**
   * 结构化展示：职位名称、级别、部门、工作模式
   * 职责列表：逐条展示岗位职责
   * 技能标签：必须技能（蓝色标签）、优先技能（灰色标签）
   * 经验要求：年限、行业、项目类型
   * 学历要求：层次、专业、是否硬性
   * 软技能：团队协作、沟通能力等
   * 加分项：技术博客、开源项目等
4. **简历匹配结果卡片**
   * 环形进度条：展示综合匹配度（0-100%），颜色随分数变化
   * 分项得分：技能匹配、经验匹配、学历匹配、软技能、加分项
   * 命中/缺失技能：清晰对比候选人与 JD 的技能重合情况
5. **面试题生成卡片**
   * 题目列表：3-5 个针对性面试问题
   * 题型覆盖：技术题、行为题、场景题
   * 关联弱点：优先针对候选人缺失技能出题
6. **推荐结论卡片**
   * 结论类型：绿色（推荐）、黄色（待定）、红色（不推荐）
   * 推荐理由：AI 生成的评估说明
   * 决策依据：匹配度分数、核心技能满足情况

### **历史记录页**

**功能模块**：

* 搜索栏：按任务内容关键词搜索
* 记录列表：卡片式展示历史匹配记录
* 分页组件：支持页码跳转
* 操作按钮：查看详情、删除单条、清空全部

## **4. 数据与账号**

**需要长期保存的内容**：

* JD 解析结果：岗位信息、技能要求、经验要求
* 简历文件：PDF/Word 文件提取后的文本内容
* 匹配记录：匹配度分数、推荐结论、生成时间
* 面试题记录：为每个候选人生成的面试题目
* 执行日志：LLM 调用次数、token 消耗、缓存命中情况

**账号体系**：

* 当前版本不涉及用户注册登录
* 历史记录保存在本地，无多用户隔离

**文件上传**：

* 支持 PDF、Word 格式简历文件上传
* 文件大小限制 5MB
* 纯本地提取文字，不调 LLM

## **5. 业务规则与逻辑**

### **JD 解析规则**

* 自动提取：职位名称、级别、部门、工作模式、职责、技能要求、经验年限、学历、软技能、加分项
* 技能分类：必须技能（精通/熟练/扎实）、优先技能（熟悉/了解/优先/加分）
* 纯规则实现：关键词匹配 + 正则提取，不调 LLM
* 性能要求：单次解析 <100ms

### **简历匹配规则**

* 匹配维度：技能匹配（40%）、经验匹配（25%）、学历匹配（15%）、软技能（10%）、加分项（10%）
* 加权评分：必须技能权重 ×3，优先技能权重 ×1
* 否定语境检测：识别“不会”“不了解”“只有了解”等否定表达，避免误判
* 子串去重：防止“Spring Boot”和“Spring”重复计数
* 只对 JD 有要求的维度加权归一化，未要求维度不参与评分

### **面试题生成规则**

* 调 LLM 生成，题目 3-5 个
* 优先针对候选人缺失技能出题
* 参考 JD 要求和候选人背景
* 匹配度 <50% 时跳过面试题生成，直接不推荐

### **推荐结论规则**

* 绿色（推荐）：匹配度 ≥80%，规则直接判定
* 黄色（待定）：匹配度 50-79%，调 LLM 生成待定理由
* 红色（不推荐）：匹配度 <50%，规则直接判定，不调 LLM

## **6. 异常与边界情况**

| **场景**      | **处理方式**                              |
| ----------- | ------------------------------------- |
| JD 输入为空     | 按钮禁用，提示“请输入 JD”                       |
| 简历输入为空      | 按钮禁用，提示“请输入简历”                        |
| 文件格式不支持     | 提示“仅支持 PDF 或 DOCX 文件”                 |
| 文件过大        | 限制单文件 5MB，超限提示“文件过大”                  |
| PDF 为扫描件    | 提示“未能从文件中提取到文字”，请手动粘贴                 |
| 匹配度 <50%    | 跳过面试题生成，直接不推荐，零 LLM                   |
| 无历史记录       | 显示“暂无历史记录”空状态                         |
| 搜索结果为空      | 显示“未找到匹配记录”                           |
| 网络异常/LLM 超时 | 前端 AbortController 可中断，显示“网络错误，请稍后重试” |
| 缓存命中        | 相同 JD+简历组合 10 分钟内直接返回缓存结果             |
